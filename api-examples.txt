====================== COMPLETE END-TO-END API FLOW ======================
                        Corporate Internet Banking


==============================================================
 STEP 1: CREATE CUSTOMER (Company)
==============================================================

POST /customer/company
Request:
{
  "companyName": "Tech Corp India Pvt Ltd",
  "companyCode": "TECH001",
  "address": "123, MG Road, Bangalore - 560001"
}

Response:
{
  "success": true,
  "message": "Customer created successfully",
  "data": {
    "id": 1,
    "companyName": "Tech Corp India Pvt Ltd",
    "companyCode": "TECH001",
    "address": "123, MG Road, Bangalore - 560001",
    "status": "ACTIVE"
  }
}

  "beneficiaryName": "Vikram Mehta",
  "amount": 25000.00,
  "currency": "INR",

==============================================================
 STEP 7: CHECKER ACCEPTS TRANSACTION
 (Auto-validates: Maker ACTIVE, Customer ACTIVE, Beneficiary ACTIVE)
==============================================================

PUT /approval/1/act
Request:
{
  "checkerId": "2",
  "action": "ACCEPT",
  "remarks": "All verifications passed"
}

Response (success - validation passed, approved, debited, completed):
{
  "success": true,
  "message": "Transaction 1 accepted by checker 2",
  "data": {
    "id": 1,
    "status": "COMPLETED",
    "approvedBy": "2",
    "createdAt": "2025-07-21T12:34:55",
    "updatedAt": "2025-07-21T12:37:20"
  }
}


==============================================================
 STEP 7b: CHECKER REJECTS TRANSACTION
==============================================================

PUT /approval/1/act
Request:
{
  "checkerId": "2",
  "action": "REJECT",
  "remarks": "Insufficient funds in source account"
}

Response:
{
  "success": true,
  "message": "Transaction 1 rejected by checker 2",
  "data": {
    "id": 1,
    "status": "REJECTED",
    "approvedBy": "2",
    "rejectionReason": "Insufficient funds in source account",
    "updatedAt": "2025-07-21T12:40:00"
  }
}


==============================================================
 STEP 7c: AUTO-REJECT (when validation fails)
==============================================================

If Maker is INACTIVE, Customer is INACTIVE, or Beneficiary is INACTIVE,
the system auto-rejects when checker tries to ACCEPT:

PUT /approval/1/act
Request:
{
  "checkerId": "2",
  "action": "ACCEPT"
}

Response (auto-rejected):
{
  "success": true,
  "message": "Transaction 1 accepted by checker 2",
  "data": {
    "id": 1,
    "status": "REJECTED",
    "rejectionReason": "Maker (user ID 1) is not ACTIVE",
    "updatedAt": "2025-07-21T12:45:00"
  }
}
